VERSÃO EM SQL (POSTGRES) - TIPOS DE DADOS SUGERIDOS
==================================================

Tabela de usuários, separada por colunas. Sugestão de tipos pro Postgres:

- id                  -> SERIAL PRIMARY KEY
    Nomes de gato não são bons identificadores únicos. Sem PK e sem
    constraint de unicidade, nada impede duas contas colidirem (é
    exatamente o problema nebuloso/Nebuloso encontrado na Tarefa 2).

- nome                -> VARCHAR(255)

- contato             -> VARCHAR(255)
    Evitar TEXT sem necessidade; o padrão de dado é fixo (e-mail).

- tipo_permissao      -> NÃO usar VARCHAR livre.
    Opção 1: VARCHAR(10) + CHECK (tipo_permissao IN ('ADMIN','USER'))
    Opção 2: CREATE TYPE tipo_permissao AS ENUM ('ADMIN','USER');
    Isso evita inconsistência de digitação ("Admin", "admin ", etc.).

- missao_atual        -> VARCHAR(100), permitindo NULL
    (já existem registros sem missão no dossiê)

- ultima_atualizacao  -> TIMESTAMP (ou TIMESTAMPTZ p/ guardar fuso BRT)
    NUNCA VARCHAR. Guardar como texto foi o motivo de precisar caçar
    inconsistência manualmente na planilha - com TIMESTAMP o banco já
    rejeita formato inválido direto na inserção.

Enviar o CREATE TABLE aqui depois de escrito, para revisão.

GUIA - INSTALAR/CONFIGURAR POSTGRESQL NO PC DA OUTRA RESIDÊNCIA
==================================================
Cenário: Windows, só tem o instalador .exe do Postgres disponível,
e o SQL Server já está instalado/funcionando na máquina.

1. Rodar o instalador .exe. Ele já traz junto: PostgreSQL Server,
   pgAdmin 4, Stack Builder e as ferramentas de linha de comando.
2. Durante a instalação, ele pede uma senha para o superusuário
   "postgres" - anotar essa senha, é a mais importante.
3. Porta padrão: 5432. Pode deixar como está - o SQL Server normalmente
   usa 1433, então não há conflito, os dois convivem na mesma máquina.
4. Locale: pode deixar o padrão do sistema.
5. Ao terminar, abrir o pgAdmin 4 (interface gráfica, parecida com o
   SSMS do SQL Server) e conectar no servidor local com a senha do
   passo 2.
6. Para usar o "psql" pelo terminal, adicionar a pasta bin do Postgres
   ao PATH do Windows (geralmente:
   C:\Program Files\PostgreSQL\<versão>\bin ).
   Sem isso, o comando "psql" não é reconhecido fora do pgAdmin.
7. Testar com: psql -U postgres -h localhost
   (ou direto pelo Query Tool do pgAdmin).
